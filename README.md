# Joke Chatbot (Python)

A command-line chatbot built in Python for the _Utveckling med Python, grund_ course final project. The chatbot greets the user, recognizes when someone introduces themselves, tells jokes fetched live from an external API, and remembers past conversations between runs.

**GitHub repository:** https://github.com/TehFat/joke-chatbot-python

## Mål (Goal)

The goal of this project was to build a working Python program from scratch that demonstrates the core skills covered in the course: variables and data types, control flow (if/else, loops), functions, error handling, object-oriented programming (classes and inheritance), reading/writing data files, and working with an external API and library.

## Beskrivning (Description)

The chatbot can:

- Greet the user by name when introduced (e.g. "my name is Fatima" or "I'm Fatima")
- Tell a random joke on request, fetched live from a public joke API
- Fall back to a generic helpful reply for anything it doesn't recognize
- Save every conversation to a JSON file and reload past conversations the next time it starts
- Keep count of how many jokes it has told during a session (via a specialized subclass)

## Metod (Method)

The project was built incrementally, one small feature at a time: starting with a basic class and a conversation loop, then adding keyword-based replies, then a real API call with error handling, then conversation history saved as JSON, and finally a subclass that extends the chatbot with joke-counting behavior. Each working piece was tested manually in the terminal before moving to the next, and each feature was committed to Git separately, so the commit history reflects the real development steps.

## Tekniska krav som uppfylls (Technical requirements covered)

- Variables and data types
- If/elif/else statements
- Loops (`while` for the conversation loop, `for` used during development/testing)
- Multiple custom functions/methods (`greet`, `respond`, `get_joke`, `load_history`, `save_history`, `add_to_history`, `joke_count`, and more)
- `try`/`except` error handling (around the API call and file loading)
- Data persistence using JSON (`chat_history.json`)
- A class with attributes and methods (`ChatBot`)
- Inheritance — `SuperChatBot` extends `ChatBot` and overrides/extends its behavior using `super()`
- A standard library module (`json`, `datetime`)
- An external library (`requests`)
- Live data from an external API (the joke API)
- A GitHub repository with a full commit history

## Hur man kör programmet (How to run it)

```bash
pip3 install requests
python3 chatbot.py
```

Type a message and press Enter. Type `exit` or `quit` to end the conversation (this also saves the conversation history).

## Resultat (Result)

The chatbot runs correctly from the command line, responds appropriately to different types of input, successfully fetches live jokes from the API (with a friendly fallback message if the request fails), and correctly saves and reloads conversation history between runs. The `SuperChatBot` subclass correctly reuses the parent class's logic through `super()` while adding its own joke-counting feature on top.

## Analys (Analysis)

The chatbot uses simple keyword matching (checking if a phrase like `"joke"` or `"my name is"` appears in the message) rather than real natural language understanding. This is a reasonable approach for a small beginner project, but it has a known limitation: a message that happens to contain multiple keywords (for example, "I'm happy, tell me a joke") could be interpreted differently than intended, since only the first matching condition in the `if/elif` chain runs. A more advanced version could use more careful text parsing or a proper natural language library, but that was outside the scope of this course project.

## Reflektion (Reflection)

Working on this project helped me understand object-oriented programming in a much more concrete way than just reading about it — actually building a class, then extending it with inheritance and seeing `super()` reuse the parent's code, made the concept click in a way theory alone hadn't. The most challenging part was getting comfortable with Python's indentation rules; several bugs during development came from a method being indented at the wrong level (for example, ending up nested inside `__init__` instead of being a proper method of the class), and learning to read those errors carefully taught me to pay much closer attention to code structure. Another good lesson was realizing that my early tests often only checked the "success" path of an `if/else` and never the other branch, which meant bugs could easily hide unnoticed — I now try to deliberately test both outcomes. If I continued developing this project, I would like to make the keyword-matching smarter and let the chatbot remember the user's name across sessions, not just within one conversation.
